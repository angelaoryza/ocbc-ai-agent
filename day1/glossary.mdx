| Term | Meaning (section where introduced) |
|----|----|
| Plan agent | OpenCode's thinking mode; advises and plans, never changes files (0.2) |
| Build agent | OpenCode's doing mode; edits files and runs commands (0.2) |
| Model | Which AI does the work; like choosing a different intern (0.4, 1.2) |
| Thinking effort | How hard the AI thinks before answering; more effort costs more (0.4, 1.3) |
| Token | A small piece of text; the unit that counts the AI's energy and cost (1.3) |
| `AGENTS.md` | The project's briefing note that OpenCode reads every time (1.4, 2.7) |
| Guardrail | A rule that keeps the system safe (1.6) |
| Front end | The page you see and click (2.2) |
| Back end | The work done out of sight (2.2) |
| Data | Where the numbers come from (2.2) |
| Loop (Plan → Implement → Test → Repeat) | The four-step cycle used for every feature (2.4) |
| Skill | A saved recipe the AI follows (2.7) |
| API | A waiter between your program and a data service (3.1) |
| `.env` | A private file that keeps secrets such as the API key (3.1) |
| **Idempotent** | Safe to run twice: the second run gives the same result, with no copies (4.2) |
| **Temperature** | How varied the AI's answers are; low is steady, high is varied (5.2) |
| **Hallucination** | An answer that sounds right but has no facts behind it (5.3) |
| **Grounding** | Giving the AI the facts and telling it to use nothing else (5.3) |
| **Prompt injection** | Instructions hidden in data that try to give the AI orders (5.5) |
| **Pydantic model** | The fixed form itself: named fields and the values each may take (5.6) |
| **AI Wiki** | Notes pages the AI keeps up to date from raw sources, and answers from (6.2) |
| **RAG** | Retrieval-augmented generation: find the closest passages, then answer only from them (6.4) |
