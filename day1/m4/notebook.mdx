## 4.1 What an LLM call is

<Info>
**The request**

Your manager: **"Before we hand the model our report, show me what a call actually sends and gets back."**
</Info>

> **In this section**
>
> - **Key question:** What goes into one call, and what comes back?
> - **How we run it:** **Live, about 5 minutes.**
> - **What you will do:** create the chat model, send a system and a human message, and read the reply.
> - **What carries forward:** `llm`, used in every section below.

A call sends a list of **messages** and gets one message back. The **system** message holds the rules, the
**human** message holds the task and the data, and the reply is an **AI** message. `ChatGoogleGenerativeAI` is
the same model setup as in `learning-agent/`; the key comes from `.env`.

```python
from langchain_google_genai import ChatGoogleGenerativeAI

llm = ChatGoogleGenerativeAI(
    model=os.getenv("GEMINI_MODEL", "gemini-3.6-flash"),
    api_key=os.getenv("GEMINI_API_KEY"),
)

messages = [
    ("system", "You answer questions about Indonesian bank stocks in one sentence. Never give buy or sell advice."),
    ("human", "What kind of company is PT Bank OCBC NISP Tbk?"),
]
response = llm.invoke(messages)
print(type(response).__name__)
print(response.text)
```

The model has no idea what "its" means: every call is **stateless**. A chat app "remembers" because it sends
the earlier messages again, with the model's own answer as an `("ai", ...)` message.

Without data the model either refuses or, worse, gives a number that looks right. With the report **between
tags**, the data is clearly separated from our instructions, and the rules say to use nothing else:

```python
SYSTEM_PROMPT = """You write a short morning digest of Indonesian bank stocks for relationship managers.
Use only the facts in the report. Quote numbers exactly, with their dates.
Never give buy, sell or hold advice, price targets or predictions."""

human_prompt = f"""<report>
{report}
</report>

Write the digest: one headline sentence, then one short sentence per bank."""

digest = llm.invoke([("system", SYSTEM_PROMPT), ("human", human_prompt)])

```

## 4.4 Prompt templates

<Info>
**The request**

Your manager: **"Tomorrow there is a new report, and every RM wants a brief on a different bank. Don't copy-paste
f-strings: make the prompt one thing we can reuse."**
</Info>

> **In this section**
>
> - **Key question:** How do we write a prompt once and fill it in for any report or bank?
> - **How we run it:** **Live, about 6 minutes.**
> - **What you will do:** turn the 4.3 prompt into a `ChatPromptTemplate`, see the messages it makes, and chain it to the model with `|`.
> - **What carries forward:** `digest_prompt` and the `prompt | llm` chain, used in 4.5, the example and Module 9.

A **prompt template** is the prompt with **blanks** in `{curly braces}`. `ChatPromptTemplate.from_messages` takes the
same `(role, text)` pairs as before; `invoke` with a dict fills the blanks and returns the messages. No model call yet:

```python
from langchain_core.prompts import ChatPromptTemplate

digest_prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM_PROMPT),
    ("human", "<report>\n{report}\n</report>\n\n{task}"),
])
print("Blanks:", digest_prompt.input_variables)

filled = digest_prompt.invoke({"report": report, "task": "Write the digest: one headline sentence, then one short sentence per bank."})
for message in filled.to_messages():
    print(type(message).__name__, "->", message.content[:80].replace("\n", " "), "...")
```

`prompt | llm` makes a **chain**: the filled messages go straight into the model. The same chain works for any report
and any task, and `chain.batch([...])` runs it for several inputs at once. A `("placeholder", "{history}")` message
would also let you pass the 4.2 conversation into a template.

```python
digest_chain = digest_prompt | llm
print(digest_chain.invoke({"report": report, "task": "In one sentence: which bank fell most over 10 days?"}).text)
```

## 4.5 Structured output

<Info>
**The request**

Your manager: **"Module 9 will raise an alert when a bank moves a lot. Code cannot read sentences; give it fields."**
</Info>

> **In this section**
>
> - **Key question:** How do we get fields we can trust from the model?
> - **How we run it:** **Live, about 8 minutes.**
> - **What you will do:** describe the fields with Pydantic, call `with_structured_output`, then design a schema of your own.
> - **What carries forward:** the `BankDigest` pattern used in the exercise, and the idea of an alert used on Day 2.

A **Pydantic** model describes the fields and their types. `llm.with_structured_output(Model)` returns a Python
object of that class, checked on the way in: a value outside a `Literal` raises an error instead of reaching your code.
`Field(description=...)` tells the model what a field means. It chains to a template like `llm` does.

```python
from typing import Literal
from pydantic import BaseModel, Field

class BankDigest(BaseModel):
    ticker: str
    last_close: int
    trend: Literal["up", "down", "flat"] = Field(description="Direction of the 10-day change")
    summary: str = Field(description="One factual sentence from the report")

class MorningDigest(BaseModel):
    headline: str
    banks: list[BankDigest]

structured_chain = digest_prompt | llm.with_structured_output(MorningDigest)
result = structured_chain.invoke({"report": report, "task": "Write the digest: one headline sentence, then one short sentence per bank."})
for bank in result.banks:
    print(bank.ticker, bank.last_close, bank.trend, "|", bank.summary)
result.model_dump()["banks"][0]
```
