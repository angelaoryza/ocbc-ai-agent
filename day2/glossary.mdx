| Term | Meaning (section where introduced) |
|----|----|
| **Control ladder** | Six rungs for who decides which data the model sees, from plain code to a triggered agent (0.2) |
| **Tool** | A function plus a description the model can read: name, description, arguments (1.1) |
| **Tool call** | The model’s request to use a tool; our code decides, runs it and returns the result (1.2) |
| **Description (of a tool)** | The text that tells the model what a tool returns, when to use it, allowed values and limits (1.3) |
| **Read tool** | A tool that fetches data and changes nothing; needs no approval (1.4) |
| **Action tool** | A tool that changes something, such as saving a note; always needs approval (1.4) |
| **Agent** | A model that repeats ask, run, read until it can answer (2.1) |
| **Plan, act, observe** | The three steps of the agent loop (2.1) |
| **Message trail** | Every message of a run in order: requests, results and the answer (2.1) |
| **Step limit** | The most tool calls an agent may make for one question; ours is six (2.1) |
| **Short-term memory** | The earlier messages passed into the next run, so follow-ups work (2.3) |
| **Today setting** | One value for today’s date that tools and instructions share (2.4) |
| **Approval** | A person decides before an action runs: Approve, Edit or Reject with a reason (3.1) |
| **Ready-made tool** | A tool supplied by a toolkit, such as web search (3.4) |
| **MCP** | Model Context Protocol: a standard socket for a provider’s tools (4.1) |
| **Host, client, server** | Our back end runs the agent (host), its MCP part makes the calls (client), the provider offers the tools (server) (4.2) |
| **Tool filter** | Keeping only chosen tools from a server, by name (4.4) |
| **Trigger condition** | A coded test that decides whether to start the agent, such as a move of 5% or more (5.1) |
| **Cooldown** | A rule that skips a ticker explained on the previous trading day (5.2) |
| **Run limit** | The most explanations one run may make; the rest are listed as not explained (5.2) |
| **Failure isolation** | One failure does not stop the rest: the alert is still saved (5.2) |
| **Red team** | Trying to break the system on purpose before a user does (6.4) |
